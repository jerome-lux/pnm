## Critical Invariants & Gotchas
1. **Never call `compute_geometry(autothroats=True)` after generation.** It erases all custom throat radii/lengths and resets every throat radius to `min(r1, r2)`, ignoring PRTRR (with PRTRR=2 this quadruples throat volume; porosity > 1). Always use `autothroats=False`; `random_PNM` already sets complete throat geometry.
2. **Pass `PRTRR` explicitly at every call site.** The `random_PNM` package default is 1, the pipeline uses 2 — omitting it makes throats twice too wide and collapses mean connectivity to ~2.7. Pore bins are always `throat_radii * PRTRR`.
3. **`inverse_transform_sampling_from_raw_data(data, bins, ...)` takes FULL bin edges** (`len(bins) == len(data)+1`). It builds the exact inverse CDF of a piecewise-uniform distribution; passing left edges only shifts every sample one bin too small (the bug that invalidated all pre-2026-11-11 study results).
4. **`compute_geometry()` relabels nodes** to consecutive integers — external references to old labels break.
5. **Node `category` is a SET of side labels** (x-, x+, y-, y+, z-, z+, inner, none; bit flags in `side_to_int_dict`). GML round-trip converts set→sorted list and `__init__(network=...)` normalizes back to set on every read path. GEXF stringifies lists/sets — **GML is the project format**.
6. **Throat-generation loops must guard with `net.graph.has_edge(n1, n2)` before accounting** surface budget/degree: `add_throat` is a silent no-op on existing edges, but unguarded accounting consumes budget for throats that do not exist ("phantom increment" bug class; fixed in v1, v2 and `add_periodic_throats`).
7. **`sratio` scales total throat count, not size composition** (measured <0.3 pt band variation 0.6→0.8 at N=80k/150k).

## Module Notes
### PNM.py
- `pore_network` wraps a `networkx.Graph`. Graph attrs: `graph_type`, `extent`, `bbox`, `porosity`, `inner_extent`, `spacing`; node attrs: `radius`, `center`, `volume`, `category` (set), `periodic`, `exchange_area`, `surface_ratio`, `boundary`; edge attrs: `radius`, `length`, `volume`, `periodic`, `pdir`.
- `write()` supports GML/GEXF/pickle via `_to_serializable` / `_sanitized_copy` helpers (ndarray→list for GML, stringified for GEXF); the live graph is never mutated on save.
- `compute_geometry()`: isolated-pore cleanup runs only when the graph has ≥1 edge — pore-only files must survive a round-trip (the param_study pore cache depends on this).
- `average_connectivity()` = 2E/N (NOT `nx.average_neighbor_degree`); `connectivity_distribution(bins=None)` returns dyadic (powers-of-two) bins by default, leading [0,1) bin keeps isolated pores so `sum(counts)==N`.

### Generators.py
- `random_PNM(..., packing_method="kdtree"|"kdtree_importance"|"opt", seed=...)`: the kdtree packers use candidate pools + vectorized clearance (cKDTree ball queries), incremental tree rebuilds, and a two-level large/small check; **bit-reproducible with `seed`** (SeedSequence spawn per restart). `nb_trials` applies to "opt" only.
- `random_PNM(throat_method="surf_v3", minc=..., large_radius_cutoff=...)`: the v3 dispatch forwards both — `minc` is the pass-1 connectivity floor and `large_radius_cutoff` (default None) enables the independent large-pore sub-network; other methods ignore them.
- `_prepare_packing_radii` fixes the original box-too-small guard (opposite-corner condition on the actual two largest radii) and an int/float N-scaling crash; `random_packing_opt` itself is reference-only and still has the old broken guard.

### Transformation.py
- **v1 `add_throats_by_surf`** (notebook default; **rewritten two-phase 2026-11-19**): phase 1 (optional, runs only when `phase1_z > 0`) seeds each pore with its `phase1_z` LARGEST-radius partners within a `(phase1_radius_factor+1)*r_i` ball (`phase1_min_neighbors` minimum candidates; subject to budget and zmax); phase 2 fills the remaining surface budget nearest-surface-distance-first over a `phase2_radius_factor*r_i + R_max` ball, processing pores in `order` ("increasing"/"decreasing"/"random"), then enforces the `phase2_zmin` connectivity floor (force-connects to nearest neighbors while keeping covered fraction < 1). `maxc` maps to zmax. The old single-pass knobs (`sort_by_radius`, `minc_search_factor`, `large_pair_radius_frac`) are now **warn-and-ignore** under "surf" — the W1 recipe of study row 20 (JSD 0.0026) is no longer reproducible and must be re-expressed in two-phase parameters before reuse.
- **v2**: phase-based with surface-gap caps (factor1/factor2), `phase1_order`; optional per-pore large-pair floor (`large_pair_radius`, `large_pair_min_connections`) — too coarse at N≤100k (K=4 already overshoots the >0.5 µm band ~3×).
- **v3**: two-pass surface-budget method. **Pass 2** (always) = the original minimal baseline: one throat at a time from randomly chosen active pores, no search-radius factors / radius sorting / max connectivity — the clean i.i.d.-inversion test bed (JSD ≈ 0.175 at N=80k vs v1's 0.063; confirms the large-band deficit is structural). **Pass 1** (optional, `large_radius_cutoff` set + `minc>0`, added 2026-11-15) = an *independent* large-pore sub-network: pores with r ≥ cutoff are interconnected to other such pores (dedicated cKDTree over the large class only) until each has ≥ `minc` connections within the large class, processed largest-first like v1/v2 phase 0, partners chosen by surface distance (no size sort), greedy within budget then force-connect floor. No gap cap and no size sorting on purpose (kept minimal per user); targets wide-range two-peak distributions where pass 2 alone misses large-large throats. `large_radius_cutoff=None` reproduces the original single-pass v3 exactly. Per-pore `ratio`: scalar, truncated-normal draw (4-tuple), or a diameter-dependent profile dict (`pnm.Stats.sratio_profile_values`) evaluated from each pore's radius (added 2026-11-17 — pass it to the inversion as well so budgets match).
- `add_throats_by_distribution`: prescribes the volumetric throat distribution by direct pair assignment (ascending max-hostable radius; `gap_radius_floor` auto = 3×mean NN spacing/f_gap rescues small-pore reach). Not wired anywhere yet.
- `invasion_percolation`: articulation points recomputed every N removals (`articulation_recompute_interval=100`, ~34× speedup); batch node deletion.
- `assemble_pnm` uses `complete_missing_throat_geometry()` + `autothroats=False` (see invariant 1).

### Stats.py
- Sampler contract: see invariant 3. `shift_pore_distribution(pdist, bins, shift)`: continuous size gauge (0 = exact identity; positive → smaller pores) — largely superseded by the kernel.
- `invert_pore_distribution_independent(volumes, midradii, deltaR, e)`: cdist from volumes with factor `e` + independent-pairing backward inversion (the theory.typ model).
- `invert_pore_distribution_kernel(..., PRTRR=2.0, porosity=0.35, sratio=0.8)`: exclusion-kernel fixed-point inversion; `K(i→j) = x_j·exp(−((r_i+r_j)/D_i)³) / Σ_k x_k exp(−((r_i+r_k)/D_i)³)` with budget-derived reach `D_i` (surface budget B_i=sratio·4πr_i², mean throat section ⟨S_t⟩_i, number density ρ=9φ/(4π⟨r³⟩)); backward substitution keeps the diagonal self-term coupled. Full derivation: **`doc/pore-distribution-inversion.md`**.
- `invert_pore_distribution_kernel_experimental(..., zcap=None)`: EXPERIMENTAL class-dependent-degree variant of the kernel (doc §5.5). Not used in production — unstable without a degree cap and pushes mass away from large classes; kept for research only.
- `invert_pore_distribution_kernel_waterfill(..., zcap=None)` / `invert_pore_distribution_kernel_budget(..., zcap=None)`: multi-capillary corrections of the kernel (doc §5.6). Water-filling derives a JOINT per-class (count, composition): $n_{ij} = x_j(B_i - S_t[i,j])/\langle S_t\rangle_i$; budget keeps the production kernel's partner composition unchanged and only couples the count through the budget-saturated degree $z_i = B_i/\langle S_t\rangle_i - 1$ (no free parameter in either). The budget variant REQUIRES adaptive damping (period-2 cycle without it, same as `_gamma`). Under evaluation — keep75: both shift mass to smaller classes and degrade the large band (JSD ~0.12 wf / ~0.10 bud vs ~0.02 production kernel); `zcap≈13` restores ≈production JSD. asym50_95 grid study completed 2026-11-20 (`param_study_v2 --inversions kernel_waterfill,kernel_budget`, outdir `param_study_v2_asym50_95_wf_bud_e_sr_p1z_p2f_order_150k`): budget best JSD **0.0099** (e=1.25/sr=0.4/random/p1z=0) ties the kernel's 0.0093 within MC noise with a near-exact large band (+1.8 pt vs −5.2); waterfill 0.0129; both beat the plain kernel at 63–67 % of grid cells (mean ΔJSD ≈ −0.07…−0.085); optimal e shifts 1.75→1.25 and order flips decreasing→random; budget ≥ waterfill everywhere (degree-only is sufficient). Window-dependent: keep75 still favors the production kernel.
- `invert_pore_distribution_kernel_gamma(..., PRTRR=2.0, porosity=0.35, sratio=0.8, length_stat="mean", sratio_profile=None)`: parameter-free coupled fixed-point inversion (no `e`) — step 1 divides each bin volume by $S_k\,\bar L_k^{\mathrm{model}}$, with $\bar L_k$ aggregated per class via the incomplete-gamma length moment $\langle s\rangle_{ij} = D_i\,e^{x_{ij}}\Gamma(4/3, x_{ij})$ (`length_stat="median"`: closed form $(a^3+D_i^3\ln2)^{1/3}$); adaptive damping λ=1→0.05 floor is required (period-2 cycle at sratio≤0.4 without it). `sratio_profile` (dict, see below) replaces the scalar sratio in the per-class budget — **it changes the pore target itself** (lowering large-pore sratio shortens model gaps → more predicted large throats → larger pores; study 2026-11-17). Full derivation + validation: **`doc/capillary-length-phase2.md`**.
- `sratio_profile_values(radii, profile)` / `sratio_profile_tag(profile)`: diameter-dependent surface-coverage ratio — dict `{sr_small, sr_large, r_lo_um, r_hi_um}`, log-linear decrease in pore radius over [r_lo, r_hi], clamped outside; tag form `"p{sr_small}-{sr_large}@{r_lo}-{r_hi}"`. The SAME dict must be passed to the inversion (`sratio_profile`) and v3 generation (`ratio=`) so model and generator budgets match.
- `invert_pore_distribution_kernel_gamma_hybrid(..., m_switch=0.03, tail_exponent=0.5)`: hybrid step-1 length variant of the gamma inversion (derived profile up to 0.03 µm + power-law tail beyond it). Tested and rejected as a reference recipe on keep75 (best JSD 0.0234 at β=0.3 vs kernel e=1.25's 0.0195); kept for research only — see doc §7.2.
- `save_distributions(pn, bins, out_base, pore_bins=None)`: MIP-format semicolon CSVs — always pass `pore_bins = throat_radii * PRTRR`.
- `jensen_shannon_divergence`: the study ranking metric (symmetric, finite on disjoint supports).

### mip.py
- `MIPData` frozen dataclass + `load_mip_data(filepath, cumulative_proba=0.95, rmin=None, rmax=None)`: bin edges (n_bins+1), normalized per-bin volumes, plus raw unfiltered `diameters`/`volumes_cum`. Shared by the notebook and param_study.

### Algorithms
- `mercury_intrusion`: stack-based BFS (~2.3× faster than the original scan; results equivalent <1 % volume).
- `molecular_diffusion`: vectorized COO matrix assembly (~0.09 s at 5k pores); scipy cg rtol/tol fallback.

### Visualization.py
- `Fast3DViewer` (default) and legacy `PNM_3d_viewer`; all attribute access guarded with `.get()`.

## Performance Reference
- Packing is sub-linear (~1.7 s at N=1e4, ~11–12 s at N=1e5, ~33–36 s at N=2e5); **throat generation dominates at scale** and scales ~linearly in N (cut0.5/minc=2: ~45–55 s per run at N=1e5, ~85–100 s at N=2e5; valley-cutoff recipes are slower — more forced pass-1 connections). v1 produces far more throats than v2 (N=200k: 1.44 M vs 508 k) — expect longer MIP/VTK times.
- **Parallel generation**: `pnm.parallel_random_PNM(specs, n_jobs)` (Generators.py) generates several networks in forked workers — each spec is a dict of `random_PNM` kwargs; `"pores"` may be a pickle path (read inside the worker, so large graphs never cross the process boundary); `"out_path"` saves GML and returns a summary dict instead of the graph. Root script `generate_best_networks.py` uses it for the 4 best-recipe N=250k networks: ~3 min packing (sequential, cached in `examples/networks/pores_250000/`) + ~10 min parallel throat generation + GML writes (212–460 MB each) ≈ 20 min wall total.
- `param_study.py`: pore cache (one pack per (e, shift) — or per (e, sratio) with `--inversion kernel` — pickled in `outdir/pores/`), `--n-jobs` forked workers (~2.9× at N=80k with 4; bit-identical to sequential), per-band + large-pore connectivity columns, `--append`. Also supports: `--keep-frac` (symmetric cumulative-volume window on the base MIP), `--minc-grid`, `--sratio-profiles` (diameter-dependent sratio grid for kernel_gamma — mixed scalar floats and profile dicts; cache tag `_kerng_prof{tag}`; added 2026-11-17), and `--throat-method surf_v3 --large-radius-cutoff valley|<float>` (v3 pass 1; "valley" auto-detects the inter-peak valley of the base distribution). Distribution CSV filenames carry a `_minc{N}` tag (added 2026-11-16 — before that, `--minc-grid` runs clobbered each other's files) and now also `_maxc{tag}_mnf{n}` (added 2026-11-17 with the `--maxc-grid` / `--min-neighbor-factors` grid dimensions; 'inf' allowed for maxc — v1 pass 1 then fills up to the surface budget). results.csv additionally carries per-class mean-connectivity columns `degmean_lt0.1 … degmean_ge8` (fixed pore-diameter bands) + `degfrac_at_maxc`. High-sratio recipes produce more throats (sr=1.4: ~2.1 M at N=150k vs 1.2 M at sr=0.8) → generation time scales with throat count (~96–150 s per run at N=150k for sr 1.0–1.6).
- **Finite-size limit**: applies to UNTRUNCATED GM1, whose top bin sits at ≥16.5 µm throat radius (pore eligibility ≥33 µm) — the "large pore" class there has only ~13–21 members at N=80k/100k (`n_large` in `param_study_results_largepair_100k/`), so random placement alone cannot reproduce its 26 % >0.5 µm volume fraction (expected close large-large pairs scale linearly with N). In the keep75 window this is NOT a constraint: at N=1e5 there are 1305 pores ≥1.0 µm and ~681 ≥1.63 µm (top-bin eligible), and v3 pass 1 covers the >0.5 µm band without issue (measured +0.4 pt with cutoff=1.0/minc=1).
